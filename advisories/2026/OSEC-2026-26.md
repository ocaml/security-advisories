# runtime_events user event name-based type confusion

ANT-2026-DTBY2HWS 

Custom events maintains a cache of user events, it is possible to have a corrupt stream that has a valid message with one message type (which can be custom/unit/span/int) and then has the same event with a different message type.

This would never be encountered in a real program but can lead to a crash.

## Fix

Validate event type against expected type, report a corrupt stream on mismatch.

## Am I affected?

If the runtime events producer and consumer run in separate processes, and the producer can be tricked into producing malformed data.
